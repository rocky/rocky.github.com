If we have Python 3.13 installed, we can run this bytecode without the source. Note that the file name I gave is the bytecode file, not the source text.

When you have the source text, you generally have to worry less about getting the right version of Python. Since the language keeps changing, there is generally a range of Python versions that are acceptable for any given Python source text. This particular short and simple of Python source text runs on any version of Python, as far as I can tell.

But when you run a bytecode file, you need to match up the minor version level. Here it is three-thirteen. So Python three-thirteen dot 0 to three-thirteen dot nine is acceptable. 3.13.9 came out as I was drafting this slide. If Python three-thirteen dot ten comes out, that would probably be acceptable too. But any version of Python 3.12, 3.14, or 3.15 will not work.

Magic Numbers of Bytecode Files

The beginning bytes of each Python bytecode file contains a magic number. 

cb0d 0d0a: Python 3.12 (0x0dcb = 3531)
f30d 0d0a: Python 3.13 (0x0df3 = 3571)

Some non-Python magic numbers in POSIX files: 

2321     : #! script file
cafe babe: Java
7f45 4c46: ELF (executable)

#/7.2

The first two bytes of a Python bytecode file, when interpreted as a 16-bit integer, gives its magic number. The magic number for Python 3.12 is 3531 and for Python 3.13 it increases by 40 to 3571. Off to the left is this value in hex in little-endian format.

Viewers of hex dumps will recognize that the next two bytes are the ASCII characters for carriage return and line feed.

[DOWN to Magic Numbers of Bytecode Files] #/7.2 ⟶ #/7.2

The idea of storing "magic bytes" at the beginning of a file, which indicate the type of file, is not a Python concept, but instead a POSIX concept that Python and, more specifically, Python interpreters have hooked into. Here are some other common "magic bytes."

The #! that you put at the beginning of script files is, in fact, magic bytes. The Java developers got clever when they came up with the hex values "Cafe Babe" for Java's magic bytes. Note that this is not in ASCII, but in hex. That's why we can represent 4 letters in 16 bits.

The executable format name "ELF" has the ASCII character "E", "L", and "F" in the second to fourth bytes.

Identifying Python Bytecode Files

To identify Python bytecode, use pydisasm with a format specifier of "header": 

	$ pydisasm --format header five.cpython-313.pyc

Python Disassembly

Python Disassemblers:

  • Python's dis module
  • Python's pydisasm
  • pycdas from pycdc

With the previous introduction to Python bytecode, we in a better position to dig deeper in to Python bytecode. Next we are going to disassemble some Python bytecode.

There are three Python disassemblers I know about. The first comes with Python and is called dis. CPython is, by far, the most popular version of Python. If you have CPython installed, the dis module is system installed. If your Python system does not have the dis module or it doesn't work that is probably because the system does not use Python-like bytecode. Python implementations that are based on JVM, graal and the older Jython, are like this.

One big problem using Python's dis is that it can only decompile the version of Python that the interpreter is running. As I mentioned before in installing Python, you could work around this by installing several versions of Python. But another problem with using dis is that it can't handle a Python byecode file out of the box. You'd have to write some additional Python to read in the file and pass dis some unmarshalled code objects.

In Python 2 up to Python 3.5, the sequence stayed the same for the longest period. Here it is. Note that instructions came in two sizes — there were one-byte instructions and 3-byte instructions.

[DOWN to Python 3.6] #/11.4 ⟶ #11.4

Starting in Python 3.6, instructions were fixed at two bytes. So although the actual instructions are the same, the encoding changes.

[DOWN to Python 3.11] #/11.4 ⟶ #11.4

And starting in Python 3.11, there are still two instructions, but they are both different. The RESUME instruction is telling the interpreter that it's okay to start JITing instructions from this point. And the LOAD_CONST and RETURN_VALUE instructions are not folded into one instruction RETURN_CONST.

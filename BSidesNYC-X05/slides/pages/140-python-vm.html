Now we've seen a little of the workings of a Python interpreter. There are a few different interpreter implementations: CPython, PyPy and Graal are the most popular. And each interpreter has changed a bit over time. However the virtual machine all share common features. So let me show how a Python interpreter "virtual machine" world compares with real world that runs your computer when you run a statically compiled machine binary.

To make things more concrete and comparable, I will compare with the environment used in running binary created from a C program.

This is how the C runtime, OS and machine hardware see things. How about inside the Python virtual machine and interpreter? Even though, in Python, you find things that seem similar to the C world, they are a bit different. For example, Python has a built-in "int" type which is sort of like a C "int." But integers, in Python, meld into what is called "BigNum's." They can get arbitrarily large.

While C has fixed-length arrays, and memory areas similar to Python's "list"; "list," "tuple," "dict," and "set" can grow and shrink without a specific memory allocation of them. To support this Python has aa automatic memory allocation and garbage collection which we will describe later.

As we saw before, Python instruction are somewhat higher level because they work on higher-level ojjects. For example there is a bytecode instruction to append a Python object to an existing Python list. Some of the compactness in instruction-set size has to do with referring to implicit operands on an evaluation stack.

Some of the compactness come from referring to a Python object using a short integer, like 0 or 1. And the program counter itself is small integer called an "offset." A jump address, then, is typically one byte or 8 bits, rather than 32 or 64 bits.

Next, I issue a "step" command to get to the next line, line 4. At this point, we are going to load the constant integer value 5 so that we can store it in variable x. At this point I note that the evaluation stack is empty. And I can see that using info stack.

But notice that variable x is still undefined. However, when I stepi into the STORE instruction x now has the value 5, as expected.

In the final lab topic, I want to show a way to modify Python bytecode, that is a little nicer, I think, than patching bytes in a hex editor.

The bytecode is this, is example1 that you just worked out. You might have disassembled it using pydisasm.

One of the formats using minus minus "format" or minus "F" that pydisasm has xasm format. This strips out the offset numbers from the disassembly output and turns jumps to offsets, into jumps to a corresponding assembler like label. This is the kind of thing you might find in an assembler for machine instructions. Line numbers are also preserved as labels, so they get added whether or not there is an explicit jump

This is done so that it can be input into a bytecode assembler that I wrote, that produces a Python bytecode file.

What makes this unique among, is that as we have seen, in Haggunenon style, there are well over 60 different instruction sets, for the over 60 variations of Python bytecode.

That bytecode number at the beginning of the file 3439 is therefore vewy vewy important! It specifies the opcode set and the Python code structure to use!

Bytecode in General

Bytecode is used in Java, Lua, Ethereum, Ruby, Smalltalk, various Lisps.

Here, I want to briefly compare, or put in place, Python Bytecode with other Bytecode.

The idea of bytecode goes back, as far as I can tell with the language from Xerox PARC called Self in 1987 and and SmallTalk circa 1969 to 1972. Nicklaus Wirth undoubtedly got the idea for Pascal P-Code (the P stands for "Portable").

Lisp, with its old lineage, is also no stranger to bytecode. Emacs Lisp which I've looked at, keeps more information in the evaluatation stack than Python currently does, and this makes decompilation harder, especially for LLMs which have trouble with counting and pairing expressions.

In the future though, with the introduction to JITing and the introduction of the RESUME instruction, Python may evolve look more like Emacs Lisp.

The term "bytecode" however came in vogue with the introduction of Java. Bytecode in Java is both stack-based and it has registers. But the language feels to me a little more low level in that machine word sizes do appear in the language, and there is that notion of registers.

Ethereum which supports cryptocurrency and smart contracts, is also a thing out of the Hitchiker Guide to the Galaxy. There is this virtual machine seen by all users that is supposed to represent the state of all financial transactions, contracts, etc. The language that this virtual machine runs is EVM bytecode. It too is stack based. Currently, there is no serious decompiler for this, but I think there could be one along the lines of what is done in Python compilers.

Bytecode Security

Bytecode can be reversed. In some cases it is easy to do, in some cases it can be hard. If you only need short-term security — it needs to be secure for most casual use that can't be reversed in a few hours/days/months — Python bytecode might be okay. But for long-term security, Python bytecode can be reversed.
